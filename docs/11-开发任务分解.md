# 11 开发任务分解

## 1. 执行规则

- 任务按依赖关系执行；同一模块内默认串行，模块间可并行。
- 每个任务必须有代码、测试、文档和验收证据。
- 任务拆到 0.5～2 个工作日粒度；超过 2 天继续拆分。
- 发现长期架构取舍时先新增 ADR，再继续实现。

## 9. 每个任务的完成定义

```text
实现完成
  → 类型检查通过
  → 单元/集成测试通过
  → 相关文档更新
  → 性能或兼容性证据（如适用）
  → 代码评审通过
```

## 10. 第一条可运行垂直切片

按以下顺序执行：

`T-BASE-001` → `T-MATH-001/002/003` → `T-CORE-001` → `T-ECS-001` → `T-SCENE-001` → `T-RHI-001` → `T-WGPU-001` → `T-RENDER-001/002/003` → `T-ASSET-001/002` → `T-GLTF-001` → `T-WORLD-001/002/003/004` → `T-WORLD-005`。

该切片交付“WebGPU 3D 场景 + glTF + 相机 + 四叉树瓦片 + 异步加载 + 调试统计”，之后再扩大功能面。
