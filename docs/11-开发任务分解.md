# 11 开发任务分解

## 1. 执行规则

- 任务按依赖关系执行；同一模块内默认串行，模块间可并行。
- 首要实现语言为 C++20；构建系统使用 CMake，依赖通过锁定清单管理。
- 每个任务必须有代码、测试、文档和验收证据；Web 任务必须说明与原生实现的差异。
- 任务拆到 0.5～2 个工作日粒度；超过 2 天继续拆分。
- 发现长期架构取舍时先新增 ADR，再继续实现。

## 7. 世界流式、游戏和编辑器任务

保留原 `T-WORLD-*`、`T-PHYS-*`、`T-ANIM-*`、`T-PARTICLE-*`、`T-AUDIO-*`、`T-SCRIPT-*`、`T-EDITOR-*`、`T-DEBUG-*`、`T-QA-*`、`T-PERF-*`、`T-PLUGIN-*`、`T-GIS-*` 和 `T-RELEASE-*` 编号。执行时将“Worker”解释为 C++ 任务线程，必要时再映射为 Web Worker；将“WebAudio/PWA/npm”替换为平台服务、WebHost 和静态 Web 发布。

## 8. 第一条可运行垂直切片

`T-BASE-001/002/003/005` → `T-MATH-001/002/003` → `T-CORE-001/002` → `T-ECS-001` → `T-SCENE-001` → `T-RHI-001/003` → `T-VK-001` → `T-RENDER-001/002/003` → `T-ASSET-001/002` → `T-GLTF-001`。

该切片先交付“Vulkan 原生 3D 场景 + glTF + 相机 + ECS + 调试统计”；随后执行 `T-BASE-006`、`T-WGPU-001/002` 将同一场景打包到 Web。

## 9. 每个任务的完成定义

```text
实现完成 → C++ 编译和静态检查通过 → 单元/集成测试通过
→ 原生或 Web 冒烟通过（按任务适用） → 文档和性能证据更新 → 代码评审通过
```
