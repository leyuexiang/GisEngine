# 25 M00 质量与测试配置

## 1. 范围

本文记录 `T-BASE-002` 与 `T-BASE-003` 的工程入口：编译警告、代码格式、静态检查、Sanitizer 和 CTest/GoogleTest 测试切换。

## 2. 默认质量门禁

- 项目目标默认启用严格编译警告，并将警告视为错误。
- `format` 目标会使用 clang-format 格式化 C++ 源码；`format-check` 只检查，不改写文件。
- `lint` 目标会使用 clang-tidy 与当前构建目录中的 `compile_commands.json` 做静态检查。
- `quality-check` 顺序依赖格式检查和静态检查，适合作为持续集成（CI）门禁。
- GNU/Clang 的 `native-sanitize` 预设会启用地址 Sanitizer（AddressSanitizer）与未定义行为 Sanitizer（UndefinedBehaviorSanitizer）；VS 2026 的 `vs-ninja-sanitize` 预设启用地址 Sanitizer，用于发现内存越界和释放后使用。

## 3. 常用命令

```text
cmake --preset native-debug
cmake --build --preset native-debug
ctest --preset native-debug

cmake --preset native-sanitize
cmake --build --preset native-sanitize
ctest --preset native-sanitize

cmake --build out/build/native-debug-mingw --target format-check
cmake --build out/build/native-debug-mingw --target lint
```

`format`、`format-check` 与 `lint` 需要将 clang-format、clang-tidy 加入 `PATH`。工具缺失时相应目标会失败，不会伪造检查通过的结果。

## 4. GoogleTest 切换

默认配置使用随仓库提供的 GoogleTest 1.17.0 固定源码（提交 `52eb8108c5bdec04579160ae17225d66034bd723`）构建完整单元测试，不依赖本机预编译二进制库。若需要使用系统安装的 GoogleTest，可关闭源码构建并启用系统包：

```text
cmake --preset native-debug -DGISENGINE_FETCH_GOOGLETEST=OFF -DGISENGINE_USE_SYSTEM_GTEST=ON
cmake --build out/build/native-debug-mingw
ctest --test-dir out/build/native-debug-mingw --output-on-failure
```

`GisEngineUnitTests` 通过 GoogleTest 的自动发现机制登记每个测试用例。VS 2026 下使用 Ninja 预设时，需先在 x64 开发者命令环境中执行以下命令：

```text
cmake --preset vs-ninja-debug
cmake --build --preset vs-ninja-debug
ctest --preset vs-ninja-debug

cmake --preset vs-ninja-sanitize
cmake --build --preset vs-ninja-sanitize
ctest --preset vs-ninja-sanitize
```

## 6. 已知限制

- MinGW 当前的 UCRT 链接组合在链接 GoogleTest 单元测试时缺少 `__imp__Exit` 与 `__imp_quick_exit`；生产目标和无第三方依赖的冒烟测试不受影响，完整单元测试改由 VS 2026 验证。
- MinGW Sanitizer 预设尚缺少对应运行库；日常内存安全验证使用已通过的 VS 2026 AddressSanitizer 预设。
