# 07 任务系统与多线程设计

## 1. 设计目标

借鉴参考工程的生产者-消费者任务系统，先在 C++ 原生端建立可取消、可观测、可限流的线程池，再为 Emscripten 提供 Pthreads 和单线程两种映射。核心任务契约不能暴露 `std::thread`、浏览器 Worker 或 JavaScript Promise。

## 2. 任务分类

| 类型 | 原生执行位置 | Web 映射 | 示例 |
|---|---|---|---|
| IO 任务 | IO 线程 | Fetch/Worker | 文件、网络、缓存 |
| 解码任务 | 工作线程池 | Worker 或主线程切片 | glTF、KTX2、矢量、地形 |
| CPU 计算 | 工作线程池 | Emscripten Pthreads/单线程 | 网格、碰撞、导航 |
| 游戏任务 | 游戏线程 | 浏览器主线程或专用 Worker | ECS、场景、编辑器 |
| GPU 任务 | 渲染线程 | WebGPU/WebGL 命令队列 | 上传、编码、提交 |

## 3. 任务契约

```cpp
class ITask {
public:
    virtual ~ITask() = default;
    virtual TaskId GetId() const = 0;
    virtual void Execute(TaskContext& context) = 0;
    virtual bool IsCancellable() const = 0;
};
```

任务结果必须携带版本、目标句柄和取消状态，接收方在应用前校验版本，避免节点已销毁时写入旧数据。异常通过 `TaskError` 传递，不跨线程抛出未捕获异常。

## 4. 线程池与调度

原生工作线程数默认 `max(1, hardware_concurrency - 1)`，按任务类别分离 IO、CPU 和解码队列；长任务必须分片或显式让出。优先队列需要老化机制，防止低优先级任务永久饥饿。Web 单线程构建将同一调度器改为预算驱动的协作执行。

## 5. 取消、超时和重试

取消通过引擎自有 `CancellationToken` 向下传播；Web 适配器可连接 `AbortSignal`。任务在安全检查点响应取消，超时与取消都必须释放临时缓冲区。网络错误采用指数退避，数据格式错误不自动重试。

## 6. GPU 上传队列

解码线程只产生 CPU 数据包；渲染线程 `UploadQueue` 按帧字节预算处理 Buffer/Texture 上传。上传完成后发布 `AssetResident` 或 `TileResident` 事件，渲染器只消费已驻留句柄。任何后台线程不得直接调用 RHI 创建或销毁 GPU 资源。

## 7. Web 特殊约束

Web 多线程需要 SharedArrayBuffer 与 COOP/COEP 响应头；不满足时自动退回单线程。浏览器网络、IndexedDB 和虚拟文件系统由 `WebPlatformAdapter` 注入，不允许在任务核心中出现 `fetch` 或 DOM 代码。

## 8. 可观测性与验收

每个任务记录排队、执行、等待、输入/输出字节、取消原因和错误堆栈；调试面板显示队列深度、线程利用率和上传积压。必须证明任务按优先级调度、取消无未处理异常、线程传输无不必要复制，且 GPU 上传不会制造单帧长任务。
