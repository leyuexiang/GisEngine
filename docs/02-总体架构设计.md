# 02 总体架构设计

## 1. 设计原则

1. 引擎运行时、编辑器和资产工具以 C++20 为主，不依赖浏览器或具体图形接口。
2. 渲染硬件接口（RHI，Rendering Hardware Interface）隔离 Vulkan、Direct3D 12、Metal、WebGPU 和 WebGL2。
3. 平台抽象层（PAL，Platform Abstraction Layer）统一窗口、输入、文件、线程、网络、动态库和时间。
4. 编辑器只依赖公开运行时模块；游戏发布包不包含编辑器代码。
5. 数据加载、解码、渲染抽取和 GPU 上传分离，GPU 对象只由渲染线程拥有。
6. GIS、物理、脚本和网络通过插件扩展，不能污染核心运行时。
7. Web 是受约束的发布平台：动态插件转静态注册，线程和文件能力按浏览器能力裁剪。

## 2. 分层结构

```text
产品层：游戏项目、GIS 应用、原生编辑器、命令行工具
    ↓
游戏框架层：World、Actor/Entity、Component、关卡、Prefab、Gameplay
    ↓
功能层：物理、动画、粒子、音频、脚本、导航、世界流式、GIS 插件
    ↓
运行时层：Core、反射、对象系统、ECS、任务系统、资源、序列化
    ↓
渲染层：Render Extractor、RenderGraph、材质、裁剪、渲染场景
    ↓
RHI 层：Null、Vulkan、D3D12、Metal、WebGPU、WebGL2
    ↓
平台层：Windows、Linux、macOS、Web/Emscripten
```

依赖只能向下。`Runtime` 不允许包含 `Editor` 头文件；`Core` 不允许包含操作系统、图形 API 或浏览器头文件。

## 3. CMake 目标与目录边界

| CMake 目标 | 责任 | 不负责 |
|---|---|---|
| `GisEngine::Core` | 基础类型、内存、日志、反射、句柄、事件 | 图形和平台窗口 |
| `GisEngine::Platform` | 文件、线程、网络、窗口、输入和动态库抽象 | 游戏逻辑 |
| `GisEngine::Math` | 数学、几何和空间参考基础类型 | 场景状态 |
| `GisEngine::Runtime` | 引擎生命周期、世界、对象和模块管理 | 编辑器面板 |
| `GisEngine::Scene` | 实体、组件、Transform、关卡和序列化 | GPU 命令 |
| `GisEngine::RHI` | 设备、队列、资源、同步和命令抽象 | 材质业务 |
| `GisEngine::Renderer` | RenderGraph、PBR、渲染场景、裁剪 | 文件读取 |
| `GisEngine::Assets` | 导入、资源注册、异步加载、缓存和烘焙契约 | 游戏玩法 |
| `GisEngine::World` | 分区、瓦片、LOD 和流式调度 | 通用渲染管线 |
| `GisEngine::Geospatial` | 椭球、ECEF、投影和局部坐标 | GPU 后端 |
| `GisEngine::Terrain` | DEM、高程网格和地形 LOD | 通用实体行为 |
| `GisEngine::Editor` | 编辑器框架、面板、撤销重做和资产工作流 | 发布运行时 |
| `GisEngine::WebHost` | Emscripten 绑定、浏览器事件和 Web 启动外壳 | 引擎业务逻辑 |

推荐目录为 `Engine/Source/Runtime`、`Engine/Source/Editor`、`Engine/Source/Platforms`、`Engine/Source/Programs`、`Engine/Plugins`、`Samples` 和 `Tests`。公开头文件与私有实现分离，减少重编译范围。

## 4. 关键运行时对象

```text
Engine
 ├─ PlatformServices
 ├─ ModuleManager
 ├─ TaskScheduler
 ├─ AssetManager
 ├─ WorldManager
 │   └─ World → Scene → EntityRegistry
 ├─ Renderer → RenderDevice
 └─ PluginManager
```

`Engine` 负责组合根和生命周期。业务模块不能自行创建不可替换的全局单例；跨模块访问通过显式服务接口或稳定句柄。

## 5. 线程与所有权

| 资源/操作 | 游戏线程 | 任务线程 | 渲染线程 | GPU 队列 |
|---|---|---|---|---|
| World/ECS | 独占写入 | 只处理声明过的数据分区 | 只读 RenderSnapshot | 不可见 |
| 文件/网络 | 调度 | IO 和解码 | 不参与 | 不可见 |
| GPU 资源 | 提交逻辑句柄 | 生成上传数据 | 创建、销毁、编码 | 执行命令 |
| RenderGraph | 提交视图配置 | 可并行准备 | 编译和编码 | 提交 |

Web 构建的“游戏线程”运行在浏览器主线程或专用 Worker，取决于部署模式；多线程依赖 SharedArrayBuffer、跨源隔离（COOP/COEP）和 Emscripten Pthreads。必须保留单线程降级路径。

## 6. 反射、序列化与模块边界

引擎需要自有的类型标识、属性元数据、对象引用和版本迁移层。首版使用显式宏/代码生成产生反射元数据，不依赖 C++ 运行时类型信息完成资产序列化。场景和资产只保存稳定 GUID、类型版本与软资源路径，不保存裸指针。

## 7. 平台能力配置

平台能力通过编译期 Feature Set 和运行时 Capability 两层表达，包括渲染后端、线程、文件系统、动态库、网络、音频、SIMD、Compute 和压缩纹理。模块通过能力查询选择实现，禁止散布平台宏。

## 8. 扩展余量

稳定扩展点包括：RHI 后端、物理后端、脚本虚拟机、资源导入器、数据源、Render Pass、编辑器工具和平台服务。新增模块必须说明依赖方向、线程归属、内存预算、Web 可用性、裁剪行为和测试策略。
