# 29 M02 渲染快照与渲染图实现记录

本文记录 `T-RENDER-001` 与 `T-RENDER-002` 的首版交付：建立游戏线程、渲染线程和渲染硬件接口（RHI，Rendering Hardware Interface）之间的稳定数据契约。本阶段不将深度缓冲、顶点/索引缓冲或具体 Vulkan 命令直接塞入示例路径，以免绕过该边界。

## 1. 实现范围

- `RenderSnapshotBuilder`：游戏线程使用构建器提取渲染项；构建时将数据按值移动到不可变的 `RenderSnapshot`，不保留场景（Scene）或实体组件系统（ECS，Entity Component System）指针。
- `RenderItem`：包含实体句柄、世界变换、网格标识、材质标识和稳定排序键。构建器拒绝零帧号、失效实体、缺失网格或缺失材质。
- `RenderSnapshot`：按“排序键、材质、网格、实体索引、实体代数”确定性排序，减少后续批处理的状态切换，并使不同运行环境得到一致提交顺序。
- `RenderGraph`：登记逻辑资源、Pass 和显式前置依赖；拒绝空调试名称、未知资源、无目标状态的访问、同一 Pass 的重复资源访问，以及尚未登记的前置 Pass。
- `CompiledRenderGraph`：合并显式依赖和同一逻辑资源的最近访问，生成稳定拓扑执行顺序和资源状态转换计划；后端可将计划映射为 Vulkan 屏障、Direct3D 12 状态转换或 WebGPU 用途切换。
- `GisEngineRender`：作为独立静态库公开 `GisEngine::Render` 目标，公开依赖数学库（Math）与渲染硬件接口（RHI），并随安装包导出头文件。

## 2. 线程与资源边界

```text
游戏线程
  └─ RenderSnapshotBuilder ──按值冻结──> RenderSnapshot
                                              │ 只读
渲染线程 ──> RenderGraph ──编译──> CompiledRenderGraph ──> RHI 后端
```

渲染图只描述本帧的逻辑资源访问和状态计划：不拥有长期 GPU 资源、不分配物理资源、不记录具体 Vulkan 命令，也不改变 RHI 的设备生命周期。这样可在 Vulkan、后续 Direct3D 12 与 WebGPU 后端之间复用同一上层顺序与屏障语义。

## 3. 验证

- `RenderSnapshotTest`：验证提取数据的值复制、确定性排序，以及无效渲染项拒绝。
- `RenderGraphTest`：验证显式依赖与资源依赖共同形成的 Pass 顺序、状态转换计划，以及未知或重复访问的拒绝。
- VS 2026 Debug：已通过 `40/40` 项 CTest，其中新增 4 项渲染模块单元测试。

## 4. 当前边界与后续工作

- 当前状态转换计划按完整资源粒度工作，尚不包含子资源范围、读写并发分析、资源别名或跨队列同步。
- 当前依赖策略为保守的最近访问串行化；未来可在访问模式与队列信息完整后释放可安全并行的 Pass。
- 下一步由 Vulkan 后端消费已编译的状态计划，并依次接入深度缓冲、顶点/索引缓冲、资源绑定和首个不透明 Pass；这些实现必须经由渲染快照和渲染图进入 RHI。
