# 05 资源与资产管线设计

## 1. 目标

建立从网络/本地文件到 CPU 解码，再到 GPU 驻留的统一资源系统，覆盖模型、纹理、材质、动画、场景和瓦片数据。

## 2. 资源 URI 与 Manifest

资源使用 URI 标识，Manifest 记录内容哈希、类型、大小、依赖和压缩格式：

```json
{
  "schemaVersion": 1,
  "uri": "asset://characters/robot.glb",
  "hash": "sha256:...",
  "type": "gltf",
  "dependencies": ["asset://textures/robot.ktx2"]
}
```

逻辑资源路径与物理存储解耦，原生端支持本地文件、Pak/分块包和网络；Web 端映射到预加载包、Fetch 和虚拟文件系统。编辑器保存源资产，Asset Cooker（资产烘焙器）生成运行时资源。

## 3. 生命周期

```text
Unloaded → Loading → Decoding → UploadQueued → Resident
                                      ↓
                                  Failed
Resident → Evicting → Unloaded
```

每个资源同时维护 CPU 引用、GPU 引用、最近使用帧和失败原因。驱逐只释放不再被引用且超过保留窗口的资源。

## 4. 格式选择

| 类型 | 首选格式 | 备用 |
|---|---|---|
| 模型 | glTF/GLB + Meshopt | Draco |
| 纹理 | KTX2/Basis | PNG/JPEG |
| 场景 | JSON（开发）/二进制（发布） | — |
| 动画 | glTF Animation | 自定义压缩 |
| 地形 | 引擎 TilePayload | 3D Tiles |

## 5. 资源管理器接口

```cpp
class IAssetManager {
public:
    virtual AssetRequest Load(AssetUri uri, const LoadOptions& options) = 0;
    virtual void Preload(std::span<const AssetUri> uris, int priority) = 0;
    virtual void Release(AssetHandle handle) = 0;
    virtual AssetStats GetStats() const = 0;
};
```

加载请求支持优先级、取消令牌、重试次数、超时和占位资源。原生端使用 `CancellationToken`，Web 端由 `AbortSignal` 适配，但上层不暴露浏览器类型。

## 6. GPU 上传

任务线程只返回可移动的解码数据和元数据；渲染线程 `UploadQueue` 按每帧字节预算批量写入 Buffer/Texture。原生端通过移动语义传递，Web 端映射为 Transferable ArrayBuffer/Worker 消息。大纹理分片上传，避免单次阻塞。

## 7. 缓存与版本

内存层使用按资源类型分桶的 LRU；原生端持久化层使用 Pak/磁盘缓存，Web 端适配 CacheStorage/IndexedDB。版本升级采用迁移函数，无法迁移时安全清理旧缓存。

## 8. 失败与降级

资源失败不应让场景崩溃：模型显示占位网格，纹理使用默认颜色，动画退化为静态姿态，瓦片回退父节点。错误必须包含 URI、阶段、原因和重试建议。

## 9. 验收标准

- 同一资源并发请求只产生一次实际加载。
- 取消请求后不再上传 GPU。
- GPU 预算超限时能按策略驱逐。
- 资源失败可观测、可重试且不会泄漏句柄。
