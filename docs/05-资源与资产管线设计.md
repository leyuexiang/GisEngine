# 05 资源与资产管线设计

## 1. 目标

建立从网络/本地文件到 CPU 解码，再到 GPU 驻留的统一资源系统，覆盖模型、纹理、材质、动画、场景和瓦片数据。

## 2. 资源 URI 与 Manifest

资源使用 URI 标识，Manifest 记录内容哈希、类型、大小、依赖和压缩格式：

```json
{
  "schemaVersion": 1,
  "uri": "asset://characters/robot.glb",
  "hash": "sha256:...",
  "type": "gltf",
  "dependencies": ["asset://textures/robot.ktx2"]
}
```

URI 与物理 URL 解耦，支持 CDN、IndexedDB、本地包和未来原生文件系统。

## 3. 生命周期

```text
Unloaded → Loading → Decoding → UploadQueued → Resident
                                      ↓
                                  Failed
Resident → Evicting → Unloaded
```

每个资源同时维护 CPU 引用、GPU 引用、最近使用帧和失败原因。驱逐只释放不再被引用且超过保留窗口的资源。

## 4. 格式选择

| 类型 | 首选格式 | 备用 |
|---|---|---|
| 模型 | glTF/GLB + Meshopt | Draco |
| 纹理 | KTX2/Basis | PNG/JPEG |
| 场景 | JSON（开发）/二进制（发布） | — |
| 动画 | glTF Animation | 自定义压缩 |
| 地形 | 引擎 TilePayload | 3D Tiles |

## 5. 资源管理器接口

```ts
interface AssetManager {
  load<T>(uri: AssetUri, options?: LoadOptions): Promise<AssetHandle<T>>;
  preload(uris: AssetUri[], priority?: number): void;
  release(handle: AssetHandle<unknown>): void;
  getStats(): AssetStats;
}
```

加载请求支持优先级、AbortSignal、重试次数、超时和占位资源。

## 6. GPU 上传

Worker 只返回 Transferable ArrayBuffer 和解码元数据；主线程 `UploadQueue` 按每帧字节预算批量写入 Buffer/Texture。大纹理分片上传，避免单次阻塞。

## 7. 缓存与版本

内存层使用按资源类型分桶的 LRU；持久化层使用 CacheStorage 保存响应，IndexedDB 保存 Manifest、解码结果索引和版本。版本升级采用迁移函数，无法迁移时安全清理旧缓存。

## 8. 失败与降级

资源失败不应让场景崩溃：模型显示占位网格，纹理使用默认颜色，动画退化为静态姿态，瓦片回退父节点。错误必须包含 URI、阶段、原因和重试建议。

## 9. 验收标准

- 同一资源并发请求只产生一次实际加载。
- 取消请求后不再上传 GPU。
- GPU 预算超限时能按策略驱逐。
- 资源失败可观测、可重试且不会泄漏句柄。
