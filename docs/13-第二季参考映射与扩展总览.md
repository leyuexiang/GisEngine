## 3. 继承与重构原则

### 3.1 直接继承

- 图层分层和 TileSource 数据源抽象。
- DEM 高程字段与规则网格地形思路。
- WGS84 椭球坐标转换和局部切平面。
- 要素、几何、节点、图元的职责分离。
- 对象池、任务池和 GPU 缓冲复用。
- 拾取、相机动画和浏览器交互的产品流程。

### 3.2 必须重构

- C++ 裸指针改为 RAII、智能指针、句柄和代数校验；只有跨 ABI 对象使用稳定句柄。
- DLL、静态链接和 Web 静态注册并存，由平台构建目标决定。
- OpenGL 状态机改为 RHI + RenderGraph；WebGPU 只是其中一个后端。
- Geometry Shader 计算改为 Compute Shader 或 CPU 备用路径；WebGPU 不保证 Geometry Shader。
- FEPK/SHP 等文件读取由原生 Asset Cooker 和运行时解码器负责，Web 端使用烘焙包或 WASM 解码器。
- Windows 事件和线程同步抽象为 Platform/Task API，Web 端再映射 Promise、AbortSignal 和 Worker 消息。

## 4. 第二季架构主题

```text
空间基准统一
  → 椭球地球与局部坐标
  → DEM 高程网格
  → 影像/高程/矢量/模型图层栈
  → 白膜和矢量渲染
  → 精度、深度、拾取、动画
  → 对象池、GPU 批处理和插件 SDK
```

任何新功能都应挂接到上述链路，而不是在应用层创建独立的“特殊地球实现”。

## 5. 第二季不纳入范围

- 不在第二季实现所有原生后端；Vulkan 先行，D3D12/Metal 可在 RHI 稳定后接入。
- 不把 PROJ4、SHP、FEPK 的全部格式细节放进核心包；它们是可选插件。
- 不在 M09～M10 同时实现完整编辑器；先提供示例、测试工具和调试面板。
- 不承诺所有浏览器均支持 Compute、时间戳查询和压缩纹理；必须有能力探测和降级。

## 6. 扩展出口

第二季完成后，第三季可以在不修改地球、DEM 和图层基本契约的前提下增加：3D Tiles、八叉树、矢量瓦片、地下模式、时态数据、网络同步、GPU 驱动的海量实例和更多原生/Web 渲染后端。
