# 08 插件与扩展系统设计

## 1. 目标

把参考工程 DLL 数据源升级为原生 C++ 插件体系，并定义可裁剪到 WebAssembly 的稳定 ABI（应用二进制接口，Application Binary Interface）。原生端允许动态库；Web 端采用构建时静态注册和显式能力裁剪，允许添加地图、矢量、物理、网络、编辑器工具和渲染 Pass。

## 2. 插件契约

```cpp
class IEnginePlugin {
public:
    virtual ~IEnginePlugin() = default;
    virtual PluginManifest GetManifest() const = 0;
    virtual bool Initialize(PluginContext& context) = 0;
    virtual void Shutdown() = 0;
};
```

插件通过能力声明申请接口，不直接访问内部单例。初始化顺序由依赖图决定，循环依赖直接报错。

## 3. 扩展点

- `TileSourcePlugin`：XYZ/TMS/WMTS/3D Tiles/游戏 Chunk。
- `AssetDecoderPlugin`：自定义模型、影像、矢量和压缩格式。
- `RenderPassPlugin`：后处理、调试可视化和特殊材质。
- `PhysicsBackendPlugin`：Rapier 或其他物理后端。
- `ScriptRuntimePlugin`：脚本语言和沙箱。
- `EditorToolPlugin`：编辑器面板、Gizmo 和导入器。

第二季新增的空间参考、DEM、图层、格式和矢量能力均通过这些扩展点接入，具体契约见 [16-图层与数据格式设计](./16-图层与数据格式设计.md) 和 [21-第二季扩展任务分解](./21-第二季扩展任务分解.md)。

## 4. 安全边界

远程插件默认不可信。原生动态库必须经过签名/版本校验并受沙箱策略约束；Web 端只允许构建时静态注册或独立 WASM 模块，通过显式消息传递。插件不能绕过 RHI 执行任意 GPU 命令、访问未授权文件或读取其他插件私有状态。

## 5. 版本与兼容

插件 API 使用语义化版本。引擎暴露能力版本、目标平台和 ABI 版本；不兼容升级需要适配层。插件资源格式必须带 schemaVersion。Web 构建还需记录是否静态注册、是否需要线程和是否包含 JS 胶水。

## 6. 生命周期

```text
Discovered → Validated → Registered → Initialized → Active → Disposing → Disposed
```

初始化失败时回滚已注册资源；销毁时先停止新任务，再等待相关任务结束，最后释放资源。

## 7. 验收标准

- 插件能注册并卸载 TileSource。
- 版本不兼容时给出明确诊断。
- 插件异常不会使主循环崩溃。
- 插件卸载后无任务、事件监听器和 GPU 资源泄漏。
