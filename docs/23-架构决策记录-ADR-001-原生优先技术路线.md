# 23 架构决策记录 ADR-001：原生优先技术路线

## 状态

已接受，2026-09-07。

## 背景

项目目标是类似 UE5 的通用 3D 游戏引擎，Web 只是打包产物。原规划把 TypeScript/WebGPU 写成核心路线，会导致编辑器、原生图形 API、线程模型、资产烘焙和高性能内存策略被浏览器约束，无法承载原生优先产品。

## 决策

1. C++20 是 GisEngine 核心运行时、编辑器、Asset Cooker 和原生插件的主开发语言。
2. CMake 是主构建系统；GoogleTest/CTest、clang 工具链和 Sanitizer 是基础质量工具。
3. RHI 先实现 Null 与 Vulkan，随后扩展 WebGPU、Direct3D 12、Metal 和 WebGL2 兼容后端。
4. Emscripten 将选定运行时编译为 WASM；JavaScript/TypeScript 仅作为 WebHost 胶水和页面集成层。
5. 原生动态插件与 Web 静态插件注册并存；插件 API、资源句柄和序列化契约保持平台无关。
6. 资产由原生 Asset Cooker 预处理，Web 只消费目标平台资源包。

## 影响

正面影响：性能、内存、线程、编辑器和原生图形能力符合 UE 类引擎定位；Web 只是清晰的目标平台，未来可加入主机和移动端。

代价：工程复杂度高于纯 Web 引擎；需要维护 CMake、多个图形后端、Emscripten 构建和平台 CI；Web 不能天然支持完整编辑器和任意动态插件。

## 迁移规则

- 保留已有 `Mxx`、`Fxx`、`T-*` 编号，变更任务语义，不复用编号。
- 旧 TypeScript 示例只作为数据契约参考；新增 C++ 接口优先，Web 类型为适配层。
- 旧 WebGPU 主路线改为 RHI 后端路线，原 Web 任务迁移到 `T-WEB-*` 和 `T-WGPU-*`。
- 任何新模块必须同时说明原生实现、Web 裁剪、线程边界、资源所有权和降级策略。

## 未决事项

- 首个原生窗口库选择 GLFW、SDL 还是自研平台层。
- ECS 采用 Sparse Set 起步还是直接采用 Archetype。
- Shader 编译链选择 DXC、shaderc、Tint/WGSL 及其许可证组合。
- 首个商业目标平台是 Windows 优先，还是 Windows/Linux 并行。
