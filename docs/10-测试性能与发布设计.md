# 10 测试、性能与发布设计

## 1. 测试分层

| 层级 | 内容 | 工具建议 |
|---|---|---|
| 单元测试 | 数学、句柄、ECS、TileKey、状态机 | Vitest |
| 集成测试 | 资产、Worker、缓存、RHI | Vitest + Mock |
| 浏览器测试 | WebGPU/WebGL2 冒烟、输入、降级 | Playwright |
| 视觉回归 | 渲染截图、材质和 LOD | Playwright + 像素阈值 |
| 压力测试 | 实体、瓦片、纹理、任务队列 | 自定义基准 |

## 2. 质量门禁

合并前必须通过：类型检查、Lint、单元测试、构建、最小 WebGPU 冒烟和 WebGL2 降级冒烟。涉及渲染或流式的改动必须附性能基准结果。

## 3. 性能预算

首个公开预览目标为 60 FPS、单帧 16.6ms：模拟约 4ms、渲染准备约 4ms、GPU 约 8ms。指标必须分设备等级记录，不以单一高端设备作为结论。

建议初始预算：

- 同时驻留纹理：移动端 256MB、桌面端 1GB，可配置。
- Worker 并发：默认最多 4 个。
- 单帧 GPU 上传：移动端 8MB、桌面端 32MB。
- 可见渲染对象：首版目标 10000 个以内。

## 4. 兼容矩阵

记录浏览器、操作系统、GPU、WebGPU 特性、压缩纹理和设备丢失行为。每次发布至少覆盖 Chromium、Firefox（若能力可用）和 Safari 的降级结果。

## 5. 发布渠道

- npm：核心包、后端包和插件 SDK。
- 示例站点：playground、terrain-demo。
- PWA：离线资源和版本缓存。
- 文档站：API、教程、迁移指南和性能建议。

## 6. 可观测性与隐私

默认只在本地记录日志和性能；若接入遥测，必须显式开关、去除资源 URL 中的敏感参数，并允许用户导出和清除诊断数据。

## 7. 发布出口

版本发布前确认：API 变更记录、资源 schema 迁移、兼容矩阵、性能回归、示例可运行、许可证和第三方声明完整。
