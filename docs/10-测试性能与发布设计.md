# 10 测试、性能与发布设计

## 1. 测试分层

| 层级 | 内容 | 工具建议 |
|---|---|---|
| 单元测试 | 数学、句柄、ECS、TileKey、状态机 | GoogleTest/Catch2 |
| 集成测试 | 资产、任务系统、缓存、RHI | CTest + Null RHI |
| 原生图形测试 | Vulkan/D3D12/Metal 冒烟、设备丢失、同步 | RenderDoc/平台 GPU 测试 |
| Web 测试 | WebGPU/WebGL2 冒烟、输入、降级 | Playwright |
| 视觉回归 | 原生与 Web 渲染截图、材质和 LOD | Golden Image + 像素阈值 |
| 压力测试 | 实体、瓦片、纹理、任务队列 | 自定义基准/Tracy |

## 2. 质量门禁

合并前必须通过：C++ 编译、clang-tidy、单元测试、Null RHI 集成测试、原生最小渲染冒烟、Web 构建和 WebGPU/WebGL2 降级冒烟。涉及渲染或流式的改动必须附性能基准结果。

## 3. 性能预算

首个原生公开预览目标为 60 FPS、单帧 16.6ms：模拟约 4ms、渲染准备约 4ms、GPU 约 8ms。Web 目标单独记录主线程、Worker、WASM 和 GPU 时间，不能直接套用原生预算。

建议初始预算：

- 同时驻留纹理：移动端 256MB、桌面端 1GB，可配置。
- 原生工作线程：默认不超过逻辑核心数减一；Web Worker/Pthreads 按能力裁剪。
- 单帧 GPU 上传：移动端 8MB、桌面端 32MB。
- 可见渲染对象：首版目标 10000 个以内。

## 4. 兼容矩阵

记录操作系统、CPU、GPU、驱动、RHI、编译器、WebGPU 特性、压缩纹理和设备丢失行为。每次发布至少覆盖 Windows Vulkan/D3D12、Linux Vulkan、macOS Metal，以及 Chromium WebGPU 和 WebGL2 降级。

## 5. 发布渠道

- 原生发行包：运行时 DLL/静态库、编辑器、Asset Cooker 和 SDK。
- Web 静态产物：WASM、JavaScript 胶水、WebGPU/WebGL2 后端和烘焙资源。
- 示例站点：playground、terrain-demo。
- 文档站：C++ API、工具链、Web 集成、迁移指南和性能建议。

## 6. 可观测性与隐私

默认只在本地记录日志和性能；若接入遥测，必须显式开关、去除资源 URL 中的敏感参数，并允许用户导出和清除诊断数据。

## 7. 发布出口

版本发布前确认：API 变更记录、资源 schema 迁移、兼容矩阵、性能回归、示例可运行、许可证和第三方声明完整。
