# 16 图层与数据格式设计

## 1. 设计目标

将影像、DEM、矢量、模型、道路和注记统一为可组合图层，同时保持格式解码、空间参考和渲染表现分离。参考工程中的 `CELLLayer` 与 `CELLFormatMgr` 演进为异步、可插拔和可观测的 TypeScript API。

## 2. 图层契约

```ts
type LayerType = 'imagery' | 'terrain' | 'vector' | 'model' | 'label' | 'custom';

interface Layer {
  id: string;
  name: string;
  type: LayerType;
  visible: boolean;
  zIndex: number;
  time?: TimeExtent;
  source: LayerSource;
  style?: LayerStyle;
}
```

图层只产生 `TilePayload` 或 `FeatureBatch`，不直接调用 Renderer。图层栈决定顺序、可见性、时间过滤和错误隔离。

## 3. 图层栈

```ts
interface LayerStack {
  add(layer: Layer): void;
  remove(id: string): void;
  reorder(id: string, zIndex: number): void;
  visibleAt(view: ViewState): ReadonlyArray<Layer>;
}
```

影像层提供颜色；DEM 层提供高度；矢量/模型层提供几何和属性。层之间通过 TileKey 和空间参考关联，不通过共享可变节点关联。

## 4. 格式注册

```ts
interface FormatHandler {
  id: string;
  extensions: string[];
  mimeTypes: string[];
  canDecode(input: ArrayBuffer, context: DecodeContext): boolean;
  decode(input: ArrayBuffer, context: DecodeContext): Promise<DecodedPayload>;
}
```

格式注册表支持版本、优先级和能力声明。首批适配：PNG/JPEG、KTX2、glTF/GLB、GeoJSON、SHP（WASM）、DEM 自定义格式和 FEPK 插件。

## 5. 文件与网络输入

- 网络：Fetch + Range 请求 + CacheStorage。
- 本地：File System Access API 或 `<input type=file>`。
- 压缩包：Worker/WASM 解包，不阻塞主线程。
- 流式：支持分块解码和背压（Backpressure）。

## 6. 图层融合

图层融合分两种：

1. 逻辑融合：多个图层分别渲染，按顺序合成，易于开关和调试。
2. 数据融合：在 Worker 中把同一瓦片的多个数据源合成一个批次，减少 Draw Call，但牺牲独立更新能力。

首版默认逻辑融合；只有在性能基准证明必要时才启用可缓存的数据融合。

## 7. 错误隔离

每层独立统计请求、解码、上传和渲染错误。图层失败显示占位或保持旧版本，不能清空其他层。格式错误应包含扩展名、MIME、字节范围和解码器版本。

## 8. 后续扩展

预留时间维度、样式表达式、属性过滤、矢量瓦片、3D Tiles、OGC API 和实时数据订阅，但不改变 Layer 基础契约。

## 9. 测试与验收

- 图层增删、排序、隐藏和时间过滤通过测试。
- 同一输入按格式版本选择正确解码器。
- 一个格式失败不影响同瓦片的其他图层。
- 多图层在相同空间参考下位置误差可控。
