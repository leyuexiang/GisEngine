# 06 世界流式与四叉树设计

## 1. 目标

将参考工程 `CELLTerrain + CELLQuadTree + CELLTileTask` 的思路抽象成通用世界流式系统，同时支持游戏 Chunk、地图影像、地形高程、矢量和 3D Tiles。

## 2. 核心契约

```ts
interface TileKey {
  level: number;
  x: number;
  y: number;
  scheme?: string;
}

interface TileSource {
  load(key: TileKey, signal: AbortSignal): Promise<TilePayload>;
}

interface TilePayload {
  bounds: Bounds;
  mesh?: DecodedMesh;
  image?: DecodedImage;
  metadata?: Readonly<Record<string, unknown>>;
}
```

`scheme` 允许未来加入四叉树、八叉树、六面体球和游戏 Chunk，而不修改 TileKey 基本接口。

## 3. 节点状态与字段

节点包含父子关系、空间边界、SSE、优先级、请求版本、资源句柄、可见性标记和最后使用帧。请求版本用于防止旧请求覆盖新状态。

状态机：

```text
Unrequested → Queued → Loading → Decoded → UploadQueued → Resident
     ↑            ↓        ↓          ↓             ↓
  Evicted ←──── Cancelled ← Failed ←───────────────┘
```

## 4. 可见性与 LOD

每帧执行：空间范围测试 → 视锥裁剪 → 屏幕空间误差估算 → 细分/合并决策 → 可渲染节点收集。子节点未驻留时继续绘制最近可用父节点。

SSE 计算需允许数据源提供误差值；没有误差值时使用可配置的几何尺寸近似。

## 5. 请求调度

优先级由距离、屏幕面积、视线方向、网络状态和用户预取共同决定。调度器需要独立的并发上限：网络、解码、GPU 上传分别限流。

必须支持：请求去重、取消、超时、指数退避、失败冷却和离线命中。

## 6. 坐标与精度

空间参考通过 `SpatialReference` 插件提供。Web Mercator 是首个实现；CPU 端保留双精度，渲染端使用局部原点。跨经度边界、极区裁剪和瓦片接缝作为独立测试集。

第二季的椭球地球、DEM 高程和曲面包围体扩展见 [14-地球椭球与空间参考设计](./14-地球椭球与空间参考设计.md) 与 [15-DEM高程地形设计](./15-DEM高程地形设计.md)。

## 7. 纹理与网格策略

- 影像瓦片优先使用纹理数组或纹理图集。
- 纹理尺寸、格式、mip 策略统一，避免动态分支。
- 地形网格支持固定网格、几何误差和边缘裙边。
- 相邻 LOD 使用边缘修补或裙边消除裂缝。

## 8. 游戏世界适配

游戏 Chunk 可以复用 TileSource 与调度器，只替换空间索引和 payload 解码器。Chunk 内部允许包含实体、碰撞体、导航数据和脚本，但这些资源仍由 AssetManager 统一管理。

## 9. 验收标准

- 相机移动时可见节点数量稳定在预算内。
- 父节点降级无明显黑块或空洞。
- 请求取消后旧响应不会改变当前节点。
- 缓存驱逐后能重新加载，节点和 GPU 资源无泄漏。
- 断网、404、解码失败和设备丢失都有可恢复路径。
