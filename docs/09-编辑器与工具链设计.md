# 09 编辑器与工具链设计

## 1. 目标

编辑器是运行时之上的应用，不反向改变核心 API。第一版聚焦场景编辑、资源检查、流式调试和可复现问题定位。

## 2. 编辑器模块

| 模块 | 责任 |
|---|---|
| 场景树 | 实体层级、过滤、选择集 |
| Inspector | 组件属性编辑、校验和重置 |
| 视口 | 相机、Gizmo、拾取、截图 |
| 资源浏览器 | Manifest、预览、导入和错误 |
| 时间轴 | 播放、暂停、单步和动画调试 |
| 性能面板 | CPU/GPU、Draw Call、显存、任务队列 |

## 3. 状态与撤销

编辑器状态与运行时状态分离；修改通过 Command 记录，支持撤销、重做和批量操作。Play Mode 使用场景快照或事务层，退出时可选择丢弃或应用改动。

## 4. 资源工具链

建议提供命令行工具：

- `engine asset inspect`：查看资源依赖和压缩信息。
- `engine asset convert`：glTF/KTX2/纹理压缩。
- `engine scene validate`：检查资源引用、schema 和包围体。
- `engine bundle build`：生成带哈希的发布包。

## 5. 调试与复现

支持导出：场景快照、输入录制、任务日志、设备能力和资源 Manifest。问题报告应能在同版本浏览器中复现。

## 6. 后续扩展

保留多人协作、脚本编辑、节点材质编辑器、地理图层面板和远程调试协议的扩展点，但不纳入首个垂直切片。

## 7. 验收标准

- 场景可以选择实体并编辑 Transform/材质。
- 撤销重做跨多个组件操作保持一致。
- 导入错误能定位到文件和字段。
- 性能面板数据与运行时统计一致。
