# 03 核心运行时设计

## 1. 模块范围

对应 `F02` 数学、`F03` ECS、`F04` 场景、`F05` 时间和输入。该模块是整个引擎最稳定的基础，不应依赖渲染后端。

## 2. 实体与句柄

实体使用 `{ index, generation }` 句柄。删除实体后递增 generation，旧句柄访问必须失败，避免参考工程裸指针产生的悬挂引用。

```ts
type Entity = {
  index: number;
  generation: number;
};
```

## 3. ECS 存储

第一版采用按组件类型的稀疏集合（Sparse Set），后续可替换为 Archetype，不改变查询接口。

```ts
interface World {
  createEntity(): Entity;
  destroyEntity(entity: Entity): void;
  add<T>(entity: Entity, type: ComponentType<T>, value: T): void;
  remove<T>(entity: Entity, type: ComponentType<T>): void;
  query<A, B>(a: ComponentType<A>, b: ComponentType<B>): Iterable<[Entity, A, B]>;
}
```

组件应是数据，不在组件内部持有 GPU 句柄或网络连接。系统负责行为，按阶段执行：`Input`、`Simulation`、`Animation`、`Streaming`、`Extract`。

## 4. 场景与 Transform

场景图只维护父子关系；每个 Transform 保存局部变换、世界变换脏标记和层级版本。深层级场景采用迭代更新，避免递归栈溢出。

需要保留的扩展点：Prefab、场景分区、实体流式、编辑器选择集和网络实体映射。

## 5. 相机与射线

相机提供透视/正交投影、视图矩阵、视锥体和屏幕射线。矩阵约定必须集中定义，明确行/列主序、左/右手坐标和深度范围，防止参考工程中跨模块隐含约定。

```ts
interface Camera {
  projection: Mat4;
  view: Mat4;
  frustum: Frustum;
  createRay(screen: Vec2, viewport: Viewport): Ray;
}
```

## 6. 时间与帧循环

固定步长模拟与可变步长渲染分离：

```text
requestAnimationFrame
  → 累积真实时间
  → 以 fixedDelta 重复执行 Simulation
  → 执行一次 Streaming/Extract/Render
```

必须限制单帧最多补偿步数，避免切后台后“螺旋死亡”。暂停、单步和时间缩放是正式 API。

## 7. 输入系统

物理输入映射到逻辑动作，例如 `MoveForward`、`PrimaryAction`、`CameraOrbit`。输入事件先进入队列，再在模拟阶段消费；这样录制和回放不依赖浏览器事件时间。

## 8. 序列化

场景文件包含 `schemaVersion`、实体 GUID、组件数据和资源 URI。加载器必须支持迁移函数；未知组件默认保留原始数据，便于编辑器和插件向前兼容。

## 9. 验收标准

- 数学核心通过随机与边界测试。
- 删除后旧实体句柄不可访问。
- 10000 个实体更新无明显 GC 峰值。
- 场景保存后可恢复层级、材质引用和实体 GUID。
- 相机射线与坐标投影在不同视口和设备像素比下结果一致。
