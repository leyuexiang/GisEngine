# 14 地球椭球与空间参考设计

## 1. 设计目标

支持平面地图、WGS84 椭球地球和局部工程坐标，并在 CPU 双精度与 GPU 单精度之间建立明确的转换边界。空间参考不能依赖某个图层或瓦片源。

## 2. 统一坐标模型

| 坐标 | 含义 | 精度 | 主要用途 |
|---|---|---|---|
| 经纬高（LLH） | 经度、纬度、椭球高 | `number` 双精度 | 对外 API、数据源 |
| 地心地固（ECEF） | 以地心为原点的三维坐标 | CPU 双精度 | 全球空间计算 |
| 局部东-北-天（ENU） | 某参考点的切平面坐标 | GPU 单精度 | 渲染、物理、拾取 |
| 瓦片坐标 | level/x/y 和边界 | 整数/双精度 | 流式调度 |
| 屏幕坐标 | 像素和深度 | 单精度 | 输入、拾取 |

## 3. 椭球模型

```cpp
class EllipsoidModel {
public:
    double semiMajorAxis;
    double semiMinorAxis;
    double eccentricitySquared;
    Vec3d GeodeticToEcef(Llh lla) const;
    Llh EcefToGeodetic(Vec3d ecef) const;
    Vec3d SurfaceNormal(Llh lla) const;
};
```

首个预置为 WGS84。接口保留自定义椭球、球体和其他基准面；高度明确是椭球高还是正高，不能用一个无语义的 `height` 字段混用。

## 4. ECEF 与 ENU

参考点 `origin: Llh` 生成 ENU 基向量。渲染快照只保存相对参考点的局部坐标和 origin 版本；相机移动导致重定位时，所有空间实体使用同一版本更新。

```cpp
class LocalFrame {
public:
    Llh origin;
    uint64_t version;
    Vec3f ToLocal(Vec3d ecef) const;
    Vec3d ToEcef(Vec3f local) const;
};
```

## 5. 空间参考接口

```cpp
class ISpatialReference {
public:
    virtual Vec3d ToWorld(GeoPosition position) const = 0;
    virtual GeoPosition FromWorld(Vec3d world) const = 0;
    virtual GeoBounds TileBounds(TileKey key) const = 0;
    virtual LocalFrame CreateLocalFrame(GeoPosition origin) const = 0;
};
```

实现包括 `wgs84-ellipsoid`、`wgs84-2d`、`web-mercator` 和未来的 PROJ/WASM 适配器。

## 6. 球面瓦片与视锥

平面四叉树的矩形 AABB 在球体上会造成极区包围误差。地球节点至少保存：经纬度范围、ECEF 包围球、局部包围盒和最大高程误差。视锥裁剪先测试包围球，再在必要时测试曲面边界。

## 7. 模型地理定位

模型放置由“经纬高 + 朝向参考系 + 缩放”组成。默认朝向使用 ENU，模型的上轴映射到局部天方向；不允许应用层手工拼接经纬度旋转矩阵。

## 8. 精度策略

- 地理计算和瓦片边界用双精度。
- GPU 上传前转换为相机相对局部坐标。
- 大坐标拆成高位/低位（High/Low）时，统一由 `precision` 模块生成。
- 物理世界采用局部坐标，重定位时暂停一步并整体迁移。

## 9. 测试与验收

- WGS84 经纬高 ↔ ECEF 往返误差有明确阈值。
- 赤道、极区、日期变更线和零经度边界通过测试。
- 不同椭球参数不会污染其他空间参考实例。
- 模型在全球多个位置的局部天方向一致。
- 原点重定位前后屏幕位置变化仅来自浮点误差预算。
