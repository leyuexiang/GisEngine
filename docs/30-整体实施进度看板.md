# 30 整体实施进度看板

本文是 GisEngine 的单页实施状态入口，记录各里程碑、渲染后端、当前验收证据、风险和下一步。详细设计以 [01-里程碑规划](./01-里程碑规划.md) 与 [11-开发任务分解](./11-开发任务分解.md) 为准；已落地能力以 `24`～`29` 号实施记录为准。

**最后更新：2026-09-08；代码基线：`f0e1585`。**

## 1. 统计口径

- **已完成**：对应范围已有代码、自动化验证或可运行示例，并满足当前切片的验收条件。
- **进行中**：已有可验证的实现，但尚未达到该里程碑完整出口条件。
- **规划中**：设计和任务已定义，尚无对应实现。
- 百分比按已实现的验收项估算，不按文档篇数、代码行数或预计工期计算；用于排序和跟踪，不作为发布日期承诺。
- M09～M14 是第二季范围，尚未启动；因此“完整路线图”不能简单将 M00～M02 的完成度外推为产品完成度。

## 4. 当前主线：M02 / R1 Vulkan

### 已完成

- **R0 Null RHI**：资源描述、类型安全句柄、状态转换、Fence 和设备丢失的自动化验证。
- **R1 Vulkan 基础**：运行时加载、设备选择、Windows 窗口表面、呈现队列、交换链、命令池、帧同步、固定版本 shaderc/glslc 着色器链和彩色三角形。
- **窗口恢复**：窗口缩放、最小化、`VK_ERROR_OUT_OF_DATE_KHR` 和 `VK_SUBOPTIMAL_KHR` 时重建交换链及对应管线。
- **渲染上层契约**：`RenderSnapshot` 按值冻结并稳定排序；`RenderGraph` 生成 Pass 执行顺序和完整资源粒度的状态转换计划。
- **验证基线**：VS 2026 Debug 与 AddressSanitizer 均通过 `40/40` CTest；`format-check`、`lint`、安装导出和差异检查通过。

### 当前完成度与边界

| 后端 / 层级 | 状态 | 当前估算 | 未完成项 |
|---|---|---:|---|
| R0 Null RHI | 已完成首版 | 100% | 后续随新 RHI 命令扩展验证器 |
| R1 Vulkan | 进行中 | 约 65%～70% | 渲染图执行、顶点/索引缓冲、深度、描述符、真实不透明场景和设备丢失恢复 |
| R2 WebGPU | 规划中 | 0% | Emscripten Canvas、设备、资源上传和同场景验证 |
| WebGL2 兼容后端 | 规划中 | 0% | 能力降级和构建裁剪 |
| R3 Direct3D 12 | 规划中 | 0% | 接口冻结后实施 |
| R4 Metal | 规划中 | 0% | 接口冻结后实施 |

### 下一交付切片

1. 让 `CompiledRenderGraph` 的执行顺序和状态转换计划驱动 Vulkan 命令录制。
2. 接入顶点/索引缓冲与 GPU 上传，替换当前无顶点缓冲的演示三角形。
3. 加入深度图像、深度测试和首个不透明 Pass；窗口重建时同步重建深度资源。
4. 加入相机常量和资源绑定，形成可提交真实网格的最小场景。
5. 增加深度资源生命周期、窗口重建和截图/绘制结果验证。

完成以上切片后，R1 的“真实几何 + 深度 + 不透明渲染链路”闭环；再以稳定的 RHI 与渲染图契约推进 R2 WebGPU 和 M03 资产系统。

## 6. 风险与决策

| 编号 | 风险 | 当前处理 | 影响 |
|---|---|---|---|
| R-01 | Vulkan 示例若继续直接堆叠功能，会绕过渲染快照和渲染图边界 | 后续深度、几何和绑定必须从 `RenderSnapshot → RenderGraph → RHI` 进入 | 高 |
| R-02 | 渲染图仍是完整资源粒度，未支持别名、子资源和跨队列同步 | 先完成单队列正确性；高阶优化留在接口稳定后 | 中 |
| R-03 | 当前 Vulkan 原生窗口路径仅验证 Windows | Linux/macOS 留待平台抽象和 R3/R4 路线验证 | 中 |
| R-04 | Emscripten/WebGPU 尚未在本机实际构建 | R1 最小真实场景稳定后安装并验证 Web 工具链 | 高 |
| R-05 | MinGW 无法完成 GoogleTest 全量链接，且 Sanitizer 运行库不完整 | 以 VS 2026 Debug 与 AddressSanitizer 作为当前完整验证基线 | 低 |
