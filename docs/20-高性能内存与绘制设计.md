# 20 高性能内存与绘制设计

## 1. 设计目标

吸收参考工程的 Pool、Task-Pool、GPU Buffer 优化和 Instance 绘制经验，降低 JavaScript 垃圾回收、Buffer 创建、Bind Group 创建和 Draw Call 开销，同时为 WebGPU Compute/Indirect 留出升级路径。

## 2. 池化范围

首批池化对象：TileNode、TaskRecord、FeatureBatch、GeometryChunk、RenderItem、UploadChunk 和临时数学数组。池对象必须有明确的 reset 逻辑，不能保留上一次场景的句柄、事件监听器或 ArrayBuffer。

## 3. GPU 缓冲池

```ts
interface BufferPool {
  allocate(size: number, usage: BufferUsage): BufferSlice;
  release(slice: BufferSlice, fence?: GpuFence): void;
  trim(targetBytes: number): void;
}
```

按 4KB、64KB、1MB 等桶分配，超大资源走独立分配。延迟回收等待 GPU 使用完成，避免复用仍在执行的 Buffer。

## 4. 实例化与批处理

相同 Mesh/Material 的对象使用实例化；实例数据包含模型矩阵、对象 ID、颜色和可选骨骼索引。矢量和白膜按图层、材质、LOD、透明模式分批。

批处理排序键固定为：渲染通道 → 管线 → 材质 → 几何 → 深度桶。排序键不包含每帧随机对象引用，避免产生临时字符串。

## 5. 间接绘制

WebGPU 高能力等级使用 Storage Buffer + Compute 生成 `DrawIndirect` 参数；CPU 路径仍生成稳定 DrawList。间接绘制不可成为核心接口的唯一形式，否则 WebGL2 无法降级。

## 6. 任务池与背压

任务对象复用但 Promise 不复用；每个任务结束时清理回调和 AbortSignal。网络、解码、GPU 上传分别设置队列上限，满载时向上游施加背压或降低低优先级预取。

## 7. 统计指标

必须统计：池命中率、分配/释放字节、GPU Buffer 数量、UploadQueue 字节、Draw Call、实例数、批次数、管线缓存命中率、Worker 队列深度和帧内 GC 迹象。

## 8. 性能演进顺序

1. 先消除每帧对象和 GPU 资源创建。
2. 再使用实例化和材质排序减少 Draw Call。
3. 再引入 GPU 裁剪和间接绘制。
4. 最后评估 GPU 法线、粒子和地形网格生成。

## 9. 测试与验收

- 池化前后基准记录 CPU 时间和内存峰值。
- GPU Buffer 延迟回收无 use-after-free。
- 批处理结果与未批处理结果像素一致。
- 低端 WebGL2 设备走 CPU DrawList，不出现 API 不支持错误。
